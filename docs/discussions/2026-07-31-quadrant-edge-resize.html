사분면 크기 조절을 엣지 드래그로

왜 한 칸만 커지지 않는가

트랙을 4분면이 공유한다

네 칸이 각자 크기를 갖는 대신, 가로 비율 하나와 세로 비율 하나가 격자 전체를 정의합니다. 그래서 한 칸을 늘리면 반대편이 정확히 그만큼 줄고, 같은 행·열의 칸도 함께 따라옵니다.

세로 경계 · cols

Q1 너비 ↑ Q2 너비 ↓
같은 열인 Q3·Q4도 함께 움직입니다.

가로 경계 · rows

Q1 높이 ↑ Q3·Q4 높이 ↓
같은 행인 Q2도 함께 움직입니다.

교차점

두 비율을 한 번에 조절합니다.
커서는 nwse-resize. 

// 비율 두 개가 곧 격자 전체 — 아래 두 줄이 레이아웃의 전부입니다.
grid.style.gridTemplateColumns = track(layout.cols, MIN_COL_PX);
grid.style.gridTemplateRows    = track(layout.rows, MIN_ROW_PX);

// minmax()의 px 하한이, 창이 작아져 드래그 클램프를 넘어설 때 칸을 지켜줍니다.
const track = (ratio, minPx) =>
  `minmax(${minPx}px, ${(ratio * 100).toFixed(3)}fr) ` +
  `minmax(${minPx}px, ${((1 - ratio) * 100).toFixed(3)}fr)`;

그랩 영역

엘리먼트 없이 좌표로 판정

잡을 대상이 되는 엘리먼트가 없으므로, 포인터와 경계선 중심 사이의 거리로 판정합니다. 간격 10px에 사분면 안쪽으로 4px씩 더해 총 18px — 항목 목록은 테두리와 패딩 때문에 7px 안쪽에서 시작하므로, 그랩 영역이 항목을 침범하지 않습니다.

/** 이 점이 어느 경계 위인지: "col" · "row" · "both" · null */
function edgeAt(x, y) {
  const m = metrics();                  // 모서리 두 칸의 rect에서 직접 계산
  const col = Math.abs(x - m.x) <= HIT;  // HIT = 10/2 + 4 = 9
  const row = Math.abs(y - m.y) <= HIT;
  if (col && row) return "both";
  return col ? "col" : row ? "row" : null;
}

커서는 상속되는 속성이라 격자에 한 번만 지정하면 사분면 경계까지 자연히 덮입니다. 드래그 중에는 포인터 캡처로 창 밖까지 따라가고, lostpointercapture가 어떤 방식으로 끝나든 리스너를 정리합니다.

도중에 발견해 고친 것

기존 코드에도 있던 결함

저장값에 null이 들어오면 Number(null) === 0 때문에 비율이 0으로 읽히고, 클램프를 거쳐 0.15로 굳어졌습니다. 기본값 0.5로 돌아가야 하는 자리입니다.

실제 숫자만 받도록 렌더러와 main.js의 IPC 핸들러 양쪽을 고쳤습니다. 마이그레이션 검증 중에 rows: null 케이스가 0.15로 나오면서 드러난 문제입니다.
